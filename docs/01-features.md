# GachaNote 功能需求文档

2026-10-24 · Can

## 1. 产品概述

GachaNote 是一款个人使用的抽卡记录与分析工具，把多款游戏、多个账号的抽卡记录集中保存在本地，并回答三个问题：现在垫了多少抽、平均多少抽出 UP、小保底歪了多少。

**目标用户**：同时玩多款二次元抽卡游戏、想长期保存并分析自己抽卡数据的玩家（首先是开发者本人）。

**要解决的问题**

- 官方抽卡记录有保留期限（米哈游游戏约 6 个月，明日方舟更短），旧记录会丢失。
- 各游戏记录分散，没有跨游戏、跨账号的统一视图。
- 官方不提供保底计数、歪率、运气评价等统计。

**不做什么**

- 不提供手动新增或修改单条抽卡记录。
- 首版不做云端账号与多端同步，数据只存在本机。
- 不做社区、排行榜等社交功能（分享图除外）。
- 不修改游戏客户端，不读取游戏内存。

## 2. 支持范围与约束

首版只做 Windows 桌面端，支持六款游戏，架构上为新增游戏、手机端和服务器同步预留扩展点。

| 项目 | 首版 | 预留扩展 |
| --- | --- | --- |
| 游戏 | 原神、崩坏：星穹铁道、绝区零（米哈游）；明日方舟、明日方舟：终末地（鹰角）；鸣潮（库洛） | 通过「游戏规则模板」新增，不改核心代码 |

| 存储 | 本地数据库（建议 SQLite） | 自建服务器同步，存储层可替换 |
| 界面语言 | 简体中文、英文 | 其他语言只需加语言包 |
| 主题 | 浅色 / 深色 / 跟随系统 | — |
| 技术栈 | Rust + Tauri + Vue | — |

**架构约束**

- 保底计算、统计分析、导入解析都放在 Rust 层，前端只负责展示，便于以后手机端和服务器复用。
- 每条记录预留同步所需字段：全局唯一 ID、导入时间、数据来源。
- 卡池元数据（卡池名、起止时间、UP 角色、常驻名单）作为独立数据包在线更新，不随软件发版。

## 4. 核心指标定义

所有指标都由各游戏的「规则模板」驱动：模板定义卡池类型、哪些卡池共享保底、硬保底抽数、每抽概率曲线、是否有大保底。下文的「金」指米哈游游戏的 5 星 / S 级、鹰角两款的 6 星。

**当前保底计数**：同一保底共享组内，从最近一次出金之后到现在的抽数。同时显示距硬保底的剩余抽数，以及下一个金是否必为 UP（大保底）。

**平均出 UP 抽数**：每个 UP 物品的花费 = 从上一个 UP（或记录起点）到本次 UP 之间的全部抽数，含中间歪掉的那一发。尾部尚未出 UP 的抽数不计入。

```latex
\bar{N}_{UP} = \frac{\sum_{i=1}^{k} n_i}{k}
```

其中 k 为获得的 UP 物品数，nᵢ 为第 i 个 UP 的花费抽数。

**小保底歪率**：只统计「小保底状态下」的出金，大保底必出的 UP 不计入分母。明日方舟没有大保底（终末地的规则待 SRS 核对），口径为「出 6 星时不是 UP 的比例」。是否歪由卡池元数据中的 UP 名单和常驻名单判断。

```latex
\text{歪率} = \frac{\text{小保底状态下歪的次数}}{\text{小保底状态下出金的次数}}
```

**出金概率预测**：设当前已垫 m 抽，模板给出第 n 抽的单抽概率 p(n)，则未来 k 抽内至少出一金的概率为：

```latex
P_k = 1 - \prod_{i=1}^{k} \left(1 - p(m+i)\right)
```

出 UP 的概率在此基础上结合当前是否大保底、UP 概率计算。

**欧非评价**：用规则模板算出「平均出金抽数」和「平均出 UP 抽数」的理论分布，给出你的实际值在分布中的百分位（如「比 78% 的人运气好」），再按百分位划分评级。样本少于 5 个金时只显示数值，不给评级。

各游戏的具体概率参数（软保底起点、武器池定轨、明日方舟 50 抽后递增等）在 SRS 阶段逐项核对后写入规则模板。

## 5. 版本规划概览

首版 v0.1 只做「文件导入与 URL 拉取 + 三项核心指标 + 总览」，先把数据模型和规则模板跑通，再逐步加入导入方式和分析功能。具体工期在开发计划文档中拆分。

1. **v0.1 MVP**：多账号、文件导入、URL 自动拉取与去重、导出、卡池元数据包、保底计数 / 平均出 UP / 歪率、记录列表、跨游戏总览、中英双语、主题切换（F-01–03, 05–13, 18, 21–23）
2. **v0.2 分析增强**：鹰角账号 token 拉取、出金分布图、月度趋势、出金概率预测、欧非评价、软件更新（F-04, 14–17, 24）
3. **v0.3 展示与分享**：卡池历史时间线、分享图生成（F-19, 20）
4. **v0.4 账号登录拉取**：官方接口登录与凭证加密存储（F-04）
5. **后续**：手机端（Android / iOS）、服务器同步、新增游戏

## 6. 待确认问题

以下问题不影响功能清单，在 SRS 阶段确定。

- [ ] 各游戏概率参数与保底共享规则逐项核对（含原神武器池定轨、集录祈愿、明日方舟限定池、终末地角色池与武器池、鸣潮角色池与武器池）。
- [ ] 数据格式原则：有成熟格式就直接用，米哈游三款采用 UIGF v4（兼容导入旧版 UIGF 与 SRGF）。鹰角两款没有 UIGF 这类通用格式，已定：兼容导入 arknights-gacha-export 导出的 CSV，另定义一个仿 UIGF 结构、保留原始字段的 JSON 用于完整备份，字段在 SRS 中定义。鸣潮同样使用这套自定义 JSON。官方记录保留期限尚未查到。
- [ ] URL 自动拉取是否允许读取游戏本地缓存文件来自动获取链接，还是只支持手动粘贴。
- [ ] 鹰角 token 拉取依赖非公开接口，接口变动时的降级策略。
